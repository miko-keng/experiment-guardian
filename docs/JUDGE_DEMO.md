# Judge demo: one connected Iris experiment

**Record this one scenario.** A researcher links a real GitLab merge request and MLflow run, sees a reproducibility warning, supplies the missing evaluation split in an Alexa+ *simulated* conversation, explicitly approves the correction, and receives a new audit report. The browser makes real MCP calls. The linked review uses real source evidence; Bedrock extraction is not needed for this path.

The exact conversational input, question, and response are below. The app's answer is deterministic, not generated by a live LLM. See [Alexa+ question and answer reference](ALEXA_QA_REFERENCE.md) for every other question the current simulation can ask and the supported replies.

## Before recording

1. Open `https://experiment-guardian.onrender.com` in Chrome, sign in privately, and let Render wake up. Never record the password or connector tokens.
2. The home page now opens **Experiments**. Under **Review an existing ML run**, enter the two values below. Leave the form ready; click **Start review** after recording begins.
3. Record the Chrome window with your microphone. Keep this guide on another device or print it.

```text
GitLab merge request URL: https://gitlab.com/miko-keng/data-science-ci-example/-/merge_requests/1
MLflow run ID:          e9cf4088-1ebe-44c5-bdcf-9c79007cad1f
```

This run previously returned seed `42`, learning rate `0.1`, dataset version `sklearn-iris`, commit `2d95c4d7e9136ea70946b6cd4cca2d8edb141729`, and accuracy about `0.8947`. The three observed findings were **Baseline run not logged**, **Run artifacts could not be verified**, and **Evaluation data split not specified**. The artifact finding means presence is **unknown**, not proved absent. Live evidence can change; read the actual status before narrating it.

## Complete conversation: no improvisation required

### After **Start session**

There is **no question to answer yet**. The session is simply ready to receive an observation. Do not click a built-in demo scenario; that would start a different experiment.

### Your one message — paste exactly

```text
The Iris run used a 75/25 data split because we wanted to keep a separate test set.
```

The pattern `75/25 data split` proposes `dataset.trainSplit = "75%"` and `dataset.testSplit = "25%"`. The word `because` also records the rationale. The code does not infer or verify the split from MLflow; the researcher is supplying it. Only approve this in the video if it matches the actual training procedure.

### Alexa+ approval question — expected exact text

> I captured dataset.trainSplit: null to "75%"; dataset.testSplit: null to "25%". Should I apply these changes and rerun the audit?

**Your answer is a click:** **Approve and re-audit**. Do not type another message. Expected reply:

> I applied the approved changes and reran the deterministic audit.

The **Evaluation data split not specified** finding should disappear from the current audit. The **Baseline run not logged** and **Run artifacts could not be verified** findings should remain open. This is the correct, honest result: adding the split does not manufacture a baseline or verify inaccessible artifacts.

### Finish — expected response

Click **Finish & report**. No further answer is needed. With the three findings above as the starting state, expected reply:

> I finished the session. The final audit has 2 open findings. I opened the detailed reproducibility report.

IDs, timestamps, and tool durations vary. If external data or code has changed the finding count, narrate the actual on-screen result and update this guide.

## Judge self-service

1. Sign in with demo credentials supplied privately by the owner.
2. Open **Experiments**, enter the MR URL and run ID above, and click **Start review**.
3. On that experiment, click **Discuss this run in the Alexa lab → Start session**.
4. Paste the one message above, click **Send to Alexa+**, then click **Approve and re-audit**.
5. Click **Finish & report**. Inspect the report, audit history, and **Actual MCP activity**.

The connected run requires server-side MLflow configuration and access. See [Connected ML experiment review](CONNECTED_ML_WORKFLOW.md). If that external connection is unavailable during judging, the separate **ResNet-50 reproducibility review** built-in scenario can still demonstrate the MCP conversation offline; its full script is in [Other demo options](DEMO_SCRIPT.md).

## The other entry points

**Audit meeting notes** remains available as a button on the **Experiments** page. It creates a review from pasted text when there is no run ID. It is useful, but it is not a step in this video. **Alexa+ Lab** can also start a standalone session, but use the **Discuss this run** link above to keep the conversation attached to the linked Iris review.
